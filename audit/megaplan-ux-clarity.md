# MEGAPLAN: UX-ясность — «хосту не нужен код» + «что такое бонусное слово»

## Контекст

Проект «Ark-sanum» (`Guessing-mages`) — vanilla HTML/CSS/JS, финский UI, все скрипты в глобальной области через `<script>`-теги. Два найденных UX-затупа:

### Проблема 1 — хост может подумать, что код надо придумать самому

В `#roomJoinView` (`index.html` ~строка 36–47) форма выглядит так:

```
[Nimesi                        ]
[KOODI          ] [🚪 Liity    ]
[🛠️ Luo huone (isännöi)        ]
```

Поле кода и кнопка «Liity» визуально стоят ПЕРЕД «Luo huone». Новый хост, читая сверху вниз, видит поле KOODI и может решить, что нужно что-то ввести/придумать код самому. Кнопка «Liity» золотая (primary) — привлекает внимание раньше «Luo huone».

### Проблема 2 — бонусное слово +25p не объяснено

Реальная механика (`js/rounds.js:462–486`, `js/ui.js:144–159`, `js/rounds.js:724–731`):

- Каждый раунд ровно ОДНО слово из 5 берётся из `words/kaikkisanat.txt` — остальные из `yleisetsanat.txt` (частые).
- «kaikki sanat» = «все слова»: словарь ПОЛНЫЙ → выпавшее слово **с большой вероятностью редкое/трудное**, но не гарантированно — там есть и обычные слова. Вводная должна передать «не только редкие», коротко.
- Это слово ВСЕГДА становится бонусным (`currentBonusWordText`), помечается бейджем `✨ +25p (Paina tätä, jos selitit!)`.
- +25p получает СЕЛИТТЯ поверх +100 за угаданное слово.
- Бонуса нет при: Sanametamorfoosi (снимает метку); словарь не загрузился (edge). Sanakaaos: 3 слова из kaikkisanat, бонус — одно случайное.

**Profanity-фильтр — ПРОВЕРЕНО и работает (verification 2026-11-10):**
- `forbiddenSet` (~700 слов, точное совпадение lowercase) применяется в `parseWords` (`js/words.js:785`) — sampled-запретные слова отсутствуют в `allWords` ✅
- Слова из непроверенной зоны отрезаны капом: `parseWords(d, 76000)` берёт только первые 76000 строк из 93086 (`js/words.js:802`, комментарий «seuraava alkaen 76000»). Проверено: `beyondLeakCount = 0` — ноль утечек за кап ✅
- Итог: `allWords` = 67820 слов, `commonWords` = 1311.
- Регрессионный тест обязан это покрывать (см. verify4 чек-лист).

Чего не понимает игрок: почему одно слово помечено, что оно из «всего словаря» (а не только редкие), есть ли оно всегда, кто получает +25.

## Проблема 1: варианты решения

### Вариант A — минимальный: разделить форму на два подписанных блока

```
[Nimesi                              ]
[🛠️ Luo huone (isännöi)  ← PRIMARY]  ← хост нажимает сразу после имени
─────────── tai liity huoneeseen ────
[KOODI (4 kirjainta)] [Liity]        ← код только в секции «liity»
```

- Делим `#roomJoinView` на два визуальных блока: верхний «Luo uusi huone», нижний «Liity olemassa olevaan».
- «Luo huone» становится акцентной золотой кнопкой, «Liity» — приглушённой (вторичный стиль).
- Поле KOODI получает placeholder «Isännän koodi» + маленькая подпись «Koodi tulee isännän ruudulta».
- Плюсы: одна правка вёрстки, ноль JS, ничего не ломает. Минусы: оба блока всё ещё на одном экране.

### Вариант B — два пути: выбор роли в одну кнопку

```
[Nimesi                              ]
[ 🛠️ Luo huone   ]  [ 🚪 Liity huoneeseen ]
        (код+кнопка появляются только если выбрали «Liity»)
```

- После имени — две кнопки-выбора. «Luo huone» сразу создаёт комнату. «Liity» раскрывает поле кода и заменяет себя на «Liity huoneeseen ABCD» (или просто активирует поле+сабмит).
- Поле кода ФИЗИЧЕСКИ не видно хосту → невозможно подумать, что его надо заполнить.
- Плюсы: максимально непротиворечиво. Минусы: гостю +1 клик; чуть больше JS (`display` переключатель).

### Вариант C — stepper/мастер (самый «магический»)

Шаг 1: «Oletko pelin isäntä?» → [Kyllä — luo huone] / [En — liity pelaajana] → шаг 2 показывает только нужное.
- Плюсы: красиво, расширяемо. Минусы: больше всего кода и кликов, перебор для 3-полевой формы.

### Рекомендация: **B** (гибрид B+A)

Кодовое поле скрыто до выбора «Liity», обе опции подписаны по роли. Дёшево в реализации и делает ошибку невозможной, а не просто менее вероятной. Если хочется ноль JS — A тоже приемлем.

Детали реализации B:
- `index.html` `#roomJoinView`: кнопки-пути `#btnPathHost`/`#btnPathJoin` (flex-row, обе `flex:1`); `#roomCodeRow` (инпут+Liity) `display:none` → показывается при выборе Liity; «Luo huone» валидирует только имя.
- `js/network.js` DOMContentLoaded: один обработчик переключения видимости + фокус в поле кода; автозаполнение `?room=ABCD` должно авто-выбирать путь «Liity» и подставлять код.
- Существующие `btnCreateRoom`/`btnJoinRoom` логика не меняется — только видимость.
- `styles.css`: вторичный стиль кнопки-пути (приглушённая, в духе `.net-mode-btn`).

## Проблема 2: варианты решения

### Вариант A — подпись-подсказка под списком слов (рекомендуется)

Под `#wordList` (или в его конец `<li>`-строкой, или фиксированная строка под списком) — приглушённый текст, показываемый только когда слова открыты:

> `✨-merkitty sana arvotaan koko sanakirjasta — usein harvinainen! Selitä se ja saat +25p.`

(«помеченное слово тянется из всего словаря — часто редкое! объясни его → +25p» — коротко передаёт и «не только редкие», и награду.)

- Реализация: `ui.js renderOlList()` добавляет `<p class="bonus-hint">…</p>` (или отдельный div `#bonusHint`, управляемый вместе со списком; скрывать в `clearWordsBeforeTurn`, при `isMetamorphosisUsedThisTurn` менять текст на «Ei bonussanaa tällä vuorolla (metamorfoosi)»).

### Вариант B — переработать сам бейдж

`✨ +25p (Paina tätä, jos selitit!)` → `✨ HARVINAINEN +25p` или `✨ Bonussana +25p`.

- Плюс: бейдж сам себя объясняет; минус: длиннее, может ломать вёрстку `li` на узком экране (проверить 320px). Можно сочетать с A: бейдж короче, детали в подписи.

### Вариант C — правило в существующие «Pelin ohjeet»/guide-блоки

- В `.spell-rules`/правила на главной добавить строку про бонус-слова (`index.html` rules-блок). Плюс: документация есть; минус: игрок читает правила до игры, а вопрос возникает у списка слов → слабо решает проблему в моменте. Делать в дополнение к A.

### Вариант D — иконка-подсказка ℹ️ у «Näytä sanat»

Кнопка `?` с тултипом/аккордеоном «Mitä ✨+25p tarkoittaa?». Плюс: компактно; минус: ещё один интерактивный элемент, тултип на тачах ненадёжен → хуже A.

### Рекомендация: **A + C**

Подпись у списка (в моменте, где возникает вопрос) + одна строка в правилах. Опционально — укоротить бейдж до `✨ +25p` раз уж подпись объясняет.

Детали реализации A:
- `index.html`: после `<ol id="wordList">` добавить `<p id="bonusHint" class="bonus-hint" style="display:none">✨-merkitty sana arvotaan koko sanakirjasta — usein harvinainen! Selitä se ja saat +25p.</p>`
- `js/ui.js`: `renderOlList` → показать `#bonusHint`, текст по умолчанию; если `isMetamorphosisUsedThisTurn` → «Ei bonussanaa tällä vuorolla.» `clearWordsBeforeTurn` → скрыть.
- `styles.css`: `.bonus-hint { font-size: 12px; color: var(--text-muted); margin-top: 6px; }`
- `index.html` rules-блок: одна короткая строка, передающая «всегда одно + из всего словаря»: `✨ Yksi sanoista tulee aina koko sanakirjasta (usein harvinainen) — selitä se, +25p.`

## План внедрения

1. `index.html`: переразметка `#roomJoinView` (вариант B) + `#bonusHint` + строка в правилах.
2. `styles.css`: `.bonus-hint`, вторичная кнопка-пути, скрытие `#roomCodeRow`.
3. `js/network.js`: переключение пути host/join; `?room=` автопуть.
4. `js/ui.js`: показ/скрытие `#bonusHint` в `renderOlList`/`clearWordsBeforeTurn`.
5. Проверить, что слово-список в room-режиме у гостей не тронут (список у них не показывается — hint тоже не нужен, но безвреден).
6. `audit/tool/verify4.js`: проверки — код-поле скрыто до «Liity», `?room=` раскрывает join-путь, `#bonusHint` виден при открытых словах и скрыт после хода, нет горизонтального скролла на 320/390px, **profanity-регрессия: все `allWords` ⊂ первых 76000 строк файла и ни одно из sample forbiddenWords не присутствует**.
7. Регрессия: verify.js (39) + verify2.js (67) + verify3.js (45) + overflow-проба.
8. Скриншоты новых состояний в `audit/screenshots/`.

## Риски / заметки

- `?room=ABCD` deep-link: обязательно автоподставлять путь «Liity» и код — сейчас это делает `netModeRoom.click()` + fill; с новым UI надо также раскрыть `#roomCodeRow`.
- Подпись `#bonusHint` не должна показываться УГАДЫВАЮЩИМ в room-режиме (они не видят слов) — она живёт в `#wordList`-блоке, который у гостей скрыт весь, ок.
- Финские формулировки держать в стиле приложения (короткие, разговорные, с эмодзи-маркером ✨ как у бейджа).
