# Мегаплан: ширина стартового экрана и мобильная полировка UI

Дата: после eee3919. Контекст: пользователь показал скриншот с телефона — стартовый экран (меню/room-панель) выглядит узкой полосой с большими пустыми полями по бокам.

## Диагноз (измерено puppeteer на 360×780)

Стартовый экран — это `#characterModal.modal-overlay` (fixed, виден по умолчанию) → `.modal-content` → `.tab-content`:

| Уровень | Отступ/ограничение | Съедает |
|---|---|---|
| `body` | padding 10px | 20px |
| `.modal-overlay` | padding 15px | 30px |
| `.modal-content` | **inline `width: 90%`** (index.html:15) + padding 20/15 | ~33px + 30px |
| `.tab-content` | padding 20px | 40px |

**Итого: ~135px хрома → usable контент ≈225px (62% экрана на 360px).** Главный виновник — inline `width:90%`, который масштабирует карточку от уже обрезанной ширины. Игровой `.container` этой проблемой не страдает (width:100%).

## Реализация

### 1. index.html — убрать inline-ширину
`style="max-height: 85vh; width: 90%; max-width: 650px; overflow-y: auto;"` → убрать `width: 90%`, оставить остальное; ширина задаётся CSS (`width:100%; max-width:650px` уже в `.modal-content`).

### 2. styles.css — мобильные медиа-запросы (≤480px, частично ≤768px)
- `.modal-overlay { padding: 8px }` (было 15) — все модалки выигрывают
- `.modal-content { padding: 14px 10px; max-width: 100% }` на ≤480px (было 20/15 + 95vw)
- `.tab-content { padding: 10px }` (было 20)
- `.modal-navigation` — проверить, что табы «Peli/Asetukset» не сжимаются
- Цель: usable ≈310–320px на 360px (~87–89% экрана); на 390+ и десктопе карточка остаётся центрированной с max-width 650px
- Без визуальной ломки: золотая рамка, радиусы и вертикальные отступы сохраняются

### 3. Точечный аудит остальных экранов на 320/360/390
Прогнать probe (элементы за краем / слишком узкие) по состояниям: меню, вкладка Asetukset, room join-панель, room-лобби (код+QR+roster), выбор мага, игровой экран, список слов + bonusHint, рисовалка, emoji-модал, victoryModal, whoGuessed, spellHelp. Что найдётся кривого — починить в том же PR (ожидаемые кандидаты: letter-spacing у `#roomCodeBig`/`h2`, длинные имена в roster, маленькие кнопки путей).

### 4. Не трогаем
- `.container` игрового экрана (уже width:100%, паддинги 18/12 — норм)
- `.player-turn-container` компенсирующие margin'ы — завязаны на паддинг `.container`; если менять его — пересчитать `calc(100%+36px)`
- Десктоп-раскладку (max-width 650 + центровка — ОК)

## Найдено и починено попутно
1. **`#drawingModalCanvas` обрезал кнопки** — inline `height:73vh` + тулбар + нижние кнопки не влезали в 800px вьюпорт → «ARVATTU OIKEIN»/«LUOVUTA VUORO» уходили за край. Заменено на `flex:1; min-height:0` — канвас занимает свободное место, кнопки всегда видны (bottom 790 ≤ 800). Размер canvas-атрибутов синкается ресайзом.
2. **verify.js: хрупкий чек ghost-fade** — мерял count пикселей alpha>0, что бинарно (края штриха остаются >0 до полного удаления): 656→656→0. Заменён на `canvasMaxAlpha` (макс. alpha) — меряет реальную рампу 255→~80→0. Плюс `bringToFront()` во всех newPage — hidden-страницы в headless мёрзнут rAF.
3. **`.modal-overlay`/`.modal-content`/`.tab-content` паддинги** — каскад ~135px на 360px экране; добавлен блок @media ≤480px + ослаблены ≤768px правила.
